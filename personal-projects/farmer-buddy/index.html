Project Overview

A digital companion for everyday farming decisions

Farmers often need information from many disconnected sources. Farmer Buddy brings the most useful categories into one clear experience and gives administrators a structured way to maintain that content.

01

The challenge

Crop information, schemes, insurance guidance, weather and educational resources are frequently spread across different channels, making them harder to discover and maintain.

02

The product idea

Create one agriculture portal where users can learn, search, ask questions and manage their profile while authorized administrators keep the information current.

03

The engineering goal

Turn a working legacy application into a well-understood, secure and maintainable personal product with a clear path toward a modern architecture.

Solution Architecture

Simple, server-rendered and database-backed

The current solution uses a classic three-layer web architecture. Pages handle the user experience, C# processes application events, and SQL Server stores platform content and user records.

My Engineering Work

From legacy application to credible personal product

I approached Farmer Buddy as both a product and an engineering-modernization exercise: understand what already exists, protect useful behavior, establish a safe foundation and improve it in deliberate phases.

01

System discovery and architecture

Mapped the application modules, user roles, page flows, database responsibilities and external-service boundaries into a clear technical model.

02

Public-safe project foundation

Prepared a clean personal-project repository with synthetic data, environment-based configuration and reproducible setup guidance.

03

Authentication and access safeguards

Introduced password hashing, database-backed administrator access and centralized protection for role-specific areas.

04

Data and upload improvements

Reconstructed a clean relational schema, completed supporting data structures and moved user uploads into a controlled private location.

05

Repeatable local delivery

Added scripts for compilation, database initialization and IIS Express startup so the project can be built and demonstrated consistently.

06

Modernization roadmap

Defined the path toward a responsive interface, parameterized data access, automated tests, modern identity and a service-oriented ASP.NET Core architecture.
